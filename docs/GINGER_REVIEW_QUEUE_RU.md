# Очередь проверки и переход по строкам — 02.11.2026

Добавлена ReviewQueue рядом с журналом строк, в каталоге с суффиксом .reviews. Отчёты создаются исключительно как новые файлы row-NNNN.json. Очередь сверяет позицию, документ, название исходного товара, снимок таблицы и hash записи кандидатов с проверенным журналом. Разрешения на запись, автоматическое сопоставление, подтверждённую свежесть или доказанное отсутствие товара отклоняются. Повторное добавление того же отчёта допустимо; отличающийся отчёт не заменяет сохранённый.

FinishReview теперь после сохранения отчёта и записи чтения добавляет его в очередь проверки. Если добавление не удалось, автоматический переход не выполняется. Новый режим NextReviewed требует подтверждения навигации и проверяет, что текущая строка прочитана и её отчёт находится в очереди. Затем используется существующий защищённый переход ровно на следующую строку. Незавершённая навигация и конец таблицы блокируют этот режим. Прежний низкоуровневый Step остаётся отдельным испытательным интерфейсом; управляемый проход должен использовать NextReviewed.

Очередь не является одобрением человеком: human_approved=false, products_processed=false. Она позволяет сохранять спорные результаты и читать следующие позиции без создания или связывания карточек. Пока нет интерфейса одобрения записей очереди и автоматического цикла по всему прайсу.

Реальная проверка: отчёт строки 3 добавлен в очередь, NextReviewed перевёл выделение на строку 4. Для строки 4 подготовлен план MAITRESSE=true, шаг выполнен через контроллер плана. Затем повторно прочитаны контексты, сохранён отчёт и добавлена вторая запись очереди. Итог: queued_positions=[3,4], текущая строка 4, незавершённых действий нет. По четвёртой строке наблюдалось 0 кандидатов; это не доказывает отсутствие товара. Сопоставлений, создания карточек, SQL-записей не было.
