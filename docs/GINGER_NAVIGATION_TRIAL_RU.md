## Чтение подключено к штатной кнопке UNIX

Кнопка «Проверить выделенный товар» теперь сначала запускает фиксированный `ReadMatchingCandidates` через новый `GingerCandidateReader`. Команды и режимы от модели не принимаются, `ConfirmNavigation` не передаётся. Скрипт включён в сборку приложения. Остановка и лимит 30 секунд используют существующий ограниченный runner с завершением дерева процесса и пределом вывода. Если чтение недоступно, сохраняется прежняя последовательность диагностики и разрешённого ею OCR.

До принятия результата Desktop проверяет структуру JSON: режим чтения, отсутствие действий, положительные наблюдаемые дескрипторы, поля исходной позиции, порядок и предел кандидатов, типы данных и явные `IdentityVerified=false`, `CanMatch=false`, `SearchCompletionVerified=false`. Последний флаг добавлен в снимок, чтобы совпадение двух наблюдений нельзя было трактовать как завершение поиска Ginger.

Отчёт с товарными текстами сохраняется только в `%LOCALAPPDATA%/BabyAI/diagnostics/ginger-candidates-<GUID>/observation.json`. В понятный журнал попадают количество кандидатов, ограничения и путь отчёта; названия и цены в журнал не копируются. Данные не передаются модели или на сервер. Существующие UI, STT/VAD и сохранённые разрешения не менялись. В Agent Runtime автоматическая навигация и запись не включались.

Проверено локально: Release-сборка Windows x64 (0 ошибок, прежнее предупреждение CS0649), .NET smoke-тесты JSON/тайм-аута/остановки/ограничения вывода, Windows fixture навигации и чтения, 33 Python-теста desktop-интеграции и guarded driver. Для предыдущего коммита `0fac58a` все три GitHub workflow завершились успешно, включая Release Bundle. В начале этой итерации Ginger был закрыт, поэтому новая связка кнопки и живого приложения не проверена; реальные чтения относятся к предыдущей итерации. Новая сборка не устанавливалась поверх пользовательского UNIX.

Следующий этап: проверка интегрированного чтения на открытом Ginger, доступных стабильных идентификаторов и сигнала завершения поиска. Автозапуск Ginger, надёжный возврат к очереди и проход всех отмеченных прайсов остаются незавершёнными.

## Чтение кандидатов каталога — проверено на реальном Ginger

Добавлен режим `ReadMatchingCandidates`: через MSAA читаются названия, исходный текст описания (в текущем Ginger содержит цену) и состояние выделения кандидатов. У наблюдавшейся пары отличается признак «тестер». Код товара в этих полях не обнаружен. Номер строки и служебный MSAA child ID не превращаются в идентификатор товара; child ID используется только для чтения того элемента, который реально вернул `AccessibleChildren`.

Панель определяется по native ListView и заголовкам «Товар»/«Цена». Число прочитанных строк сверяется с native счётчиком до и после чтения; предел — 256 кандидатов. Неизвестная структура, недостающие элементы, несколько подходящих панелей или превышение предела блокируют снимок. Исходная выделенная позиция проверяется до и после чтения кандидатов; затем повторяется весь снимок и сравниваются порядок, названия, описания, выделение, HWND панели и исходная строка.

На реальном открытом документе успешно прочитаны два кандидата. Никаких кликов, выбора кандидата или изменения данных этот режим не выполняет. `IdentityVerified=false`, `CanMatch=false` остаются обязательными результатами. Описание цены сохраняется как текст: оно не используется для расчётов. Пустой список — наблюдение, а не доказательство отсутствия товара в каталоге. Стабильность двух снимков также не доказывает, что Ginger закончил асинхронный поиск и что кандидаты относятся именно к выбранному товару; для записи этот механизм недостаточен.

Локальные Windows smoke-тесты прошли: два варианта товара и описание цены, пустой список, отсутствие/дублирование панели, предел строк, отклонение сравнения после изменения цены/названия кандидата или цены исходной позиции. Данные реального поставщика и диагностические снимки в репозиторий не добавлялись.

Следующие ограничения: получить устойчивую идентичность товара через доступные элементы UI, подтвердить завершение поиска, стабилизировать распознавание активной вкладки и завершить обход всех отмеченных прайсов. Экспериментальные скрипты ещё не подключены к штатному Agent Runtime.

## Чтение выделенного товара — проверено на реальном Ginger

Добавлен read-only режим `ReadSelectedProduct`. Он читает название, текст цены и отображаемое поле «Товар» у единственной выделенной позиции. Номер документа, поставщик, HWND таблицы, наблюдаемый номер строки и все три значения сверяются между двумя последовательными чтениями. Документ дополнительно проверяется до и после каждого чтения. Отсутствие/множественность выделения, пустые значения, неоднозначная таблица, неожиданная структура и превышение 500 строк блокируют результат.

На открытом реальном прайсе режим успешно прочитал выбранную позицию без действий ввода. `IdentityVerified=false`, `CanMatch=false` сохранены: отображаемый текст и порядковая позиция не являются идентификаторами товара. Поле цены пока возвращается как текст без финансовых вычислений. Два одинаковых чтения не обеспечивают атомарность интерфейса и не разрешают запись. Режим сам не подтверждает активность вкладки «Сопоставление - новые» — это отдельный этап навигации.

Windows smoke-тест проверяет положительное чтение, запрет выдачи разрешения на сопоставление, отсутствие выделения, две выделенные строки и пустое название. Все проверки прошли локально. Для предыдущего опубликованного коммита `8687a6c` подтверждены успешные CI, Windows Desktop и Windows Release Bundle; эти результаты не относятся к новой правке чтения.

Следующий этап — безопасно читать содержимое кандидатов каталога и установить, какие устойчивые идентификаторы действительно доступны через UI. Автоматический обход всех отмеченных прайсов и интеграция экспериментальной навигации в Agent Runtime ещё не завершены.

## Последний результат: открыт прайс и выбрана вкладка новых сопоставлений

Пользователь уточнил обязательные шаги: прайс открывается **двойным кликом** по поставщику, затем выбирается **«Сопоставление - новые»**. Простого выделения строки недостаточно. Нижние панели «Дополнительно → Сопоставление снизу» могут уже быть открыты; повторное включение не должно их закрывать.

На реальном Ginger выполнены открытие отмеченного прайса обычным вводом мыши и выбор вкладки. Визуальная проверка показала 43 новые позиции. Независимое чтение native ListView подтвердило 11 строк поисковых слов и 2 кандидата каталога. Кнопки «Связать», создания товара, заказа и проведения не нажимались. Статус остаётся `rows_observed_identity_unverified`, `CanMatch=false`: наличие кандидатов не доказывает идентичность товаров.

## Дополнение: очередь отмеченных прайсов

Режим ReadPrices читает номер, поставщика, дату, галочку и признак выделения строки через MSAA. На реальном Ginger прочитано 109 строк, 48 отмечены. ## Ограничения

Успешное открытие прайсов не заявляется. Автоматического повтора действий нет. Модуль пока не подключён к обычной кнопке приложения, не выбирает поставщиков, не читает галочки и не вызывает сопоставление. Он не содержит команд изменения товаров, заказов, печати или обращений к серверу/SQL. Для вызова из приложения необходим существующий ограниченный по времени дочерний процесс: MSAA может зависнуть внутри стороннего приложения.

Следующий шаг — ограниченное чтение заголовков и строк нестандартной таблицы через доступность, с проверкой принадлежности колонок одной таблице. Полный обход дерева уже упёрся в заданный лимит; повышать его без ограничения объёма данных нельзя. Пока достоверно не прочитаны поставщик, галочка и выбранная строка, последовательная обработка всех отмеченных прайсов заблокирована.

Существующие UI, STT/VAD, Agent Runtime и разрешения этой итерацией не изменены.
