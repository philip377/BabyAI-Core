Неизвестная структура, недостающие элементы, несколько подходящих панелей или превышение предела блокируют снимок. Исходная выделенная позиция проверяется до и после чтения кандидатов; затем повторяется весь снимок и сравниваются порядок, названия, описания, выделение, HWND панели и исходная строка.

Стабильность двух снимков также не доказывает, что Ginger закончил асинхронный поиск и что кандидаты относятся именно к выбранному товару; для записи этот механизм недостаточен.

Проверены запреты неподтверждённой навигации, неотмеченного прайса и устаревшего снимка.

Новое испытание на реальном Ginger подтвердило выбор первого отмеченного прайса: одна выделенная строка, фокус в её ячейке поставщика, 109 строк и 48 отмеченных прайсов до и после. Проверяемые номера, поставщики, даты и галочки не изменились. Никакое сопоставление не запускалось.

Ограничения: это подтверждение навигации, а не разрешение записи. CanWrite и IdentityVerified остаются false. Проверка не читает все прочие поля таблицы и не доказывает отсутствие любых побочных эффектов Ginger. Выбор невидимой ячейки блокируется; прокрутка ещё не реализована. Перед следующим действием требуется новое чтение. ConfirmNavigation — параметр экспериментального скрипта, а не подключение к системе разрешений Agent Runtime. До такой интеграции модуль нельзя считать готовой автономной функцией UNIX.

## Дополнение: очередь отмеченных прайсов

Режим ReadPrices читает номер, поставщика, дату, галочку и признак выделения строки через MSAA. На реальном Ginger прочитано 109 строк, 48 отмечены. Значение True/False каждой галочки согласовано с битом CHECKED; неопределённое состояние MIXED отвергается. Два последовательных снимка совпали. Никаких действий над строками не выполнялось.

Снимок содержит Queue: все отмеченные прайсы в исходном порядке. Несколько прайсов одного поставщика сохраняются отдельно. Повтор номера прайса, пустой поставщик (включая возвращаемый Windows маркер `(null)`), неизвестное состояние галочки, изменение между чтениями, несколько таблиц или превышение 500 строк блокируют результат целиком. Сырые данные поставщиков сохранены только локально для проверки, в GitHub не отправляются.

Локальный Windows-тест подтвердил очередь 1,3 из трёх строк с галочками True,False,True, а также отказ при дублях, пустом поставщике и противоречивых состояниях галочки. Эти тесты входят в существующую проверку Windows Desktop CI.

Это очередь наблюдений, а не разрешение действий: IdentityVerified=false и CanWrite=false. Совпадение двух чтений не гарантирует неизменность экрана после возврата. Перед будущим выбором прайса потребуется новое чтение, проверка номера/поставщика/даты/галочки и отдельная проверка фактического выделения после выбора. Переход «Дополнительно → Сопоставление снизу» ещё не реализован. Скрипт остаётся экспериментальным, к Agent Runtime и обычной кнопке приложения не подключён.

## Дополнение: распознавание реальной таблицы

Причина прежнего отказа установлена: открытая таблица имеет роль MSAA TABLE (DataGridView), без отдельного SysHeader32. Реальное имя колонки — «Вкл в сводный». Теперь драйвер читает только первые четыре дочерних элемента таблицы и до 64 ячеек строки заголовков, без обхода строк данных и без чтения значений товаров.

Повторная проверка реального Ginger в режиме Inspect вернула `prices_visible=true`, `actions=[]`: найдена ровно одна таблица с колонками «Номер», «Поставщик», «Дата», «Вкл в сводный». Это подтверждает текущий экран прайсов, но не доказывает причину его открытия и не означает готовность сопоставления.

Локальные тесты на настоящем WinForms DataGridView прошли: корректные заголовки распознаются, неверная колонка, скрытые заголовки, отсутствие и неоднозначность таблиц отвергаются. Галочки, выбранная строка и очередь поставщиков ещё не читаются. Ниже сохранён журнал первой попытки для объяснения предыдущего ограничения.

## Реализовано и проверено

Экспериментальный `scripts/windows/ginger-navigation.ps1` использует Windows PowerShell 5.1 и MSAA. По умолчанию выполняется только Inspect. OpenPrices разрешает ровно два пункта меню: «Журналы» и его дочерний «Текущие прайс-листы». Проверяются единственный процесс Ginger4, владелец окна, отсутствие отдельного модального окна, полный путь меню, единственность пункта и его доступность непосредственно перед действием. Координаты и сохранённые индексы элементов не используются.

На отдельном собственном окне тест проверил распознавание пути, отказ для посторонней команды, неверного процесса и отключённого пункта, однократный вызов разрешённого пункта и отказ считать отсутствующую таблицу найденной. Проверка добавлена в Windows Desktop CI. Это не проверка всей цепочки поставщиков.

На реальном Ginger 4.1.3.92 оба пункта прочитаны по названиям. Выполнена одна попытка перехода через стандартное действие доступности. Вызовы вернулись без исключения, но после 10 секунд таблица не подтверждена: стандартные SysHeader32 с колонками «Поставщик» и «Входит в сводные» отсутствуют. Повторная проверка только чтением также не обнаружила такие заголовки. UIA показывает другой набор элементов, но этого недостаточно для подтверждения правильного экрана.

## Ограничения

Успешное открытие прайсов не заявляется. Автоматического повтора действий нет. Модуль пока не подключён к обычной кнопке приложения, не выбирает поставщиков, не читает галочки и не вызывает сопоставление. Он не содержит команд изменения товаров, заказов, печати или обращений к серверу/SQL. Для вызова из приложения необходим существующий ограниченный по времени дочерний процесс: MSAA может зависнуть внутри стороннего приложения.

Следующий шаг — ограниченное чтение заголовков и строк нестандартной таблицы через доступность, с проверкой принадлежности колонок одной таблице. Полный обход дерева уже упёрся в заданный лимит; повышать его без ограничения объёма данных нельзя. Пока достоверно не прочитаны поставщик, галочка и выбранная строка, последовательная обработка всех отмеченных прайсов заблокирована.

Существующие UI, STT/VAD, Agent Runtime и разрешения этой итерацией не изменены.
