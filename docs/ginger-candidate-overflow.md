# Слишком широкий список кандидатов Ginger

## Реальная проверка 28 ноября 2026

Установленная версия 96496ba прошла чтение открытого прайса из 165 строк. Первое чтение заняло около 47 секунд. Две позиции без кандидатов после проверки фильтров сохранены в отложенные; переход ко второй строке подтверждён. На переходе к третьей драйвер получил `Candidate read limit exceeded: observed 278, maximum 256` и завершился с кодом 1. Это новый предел чтения списка, а не прежний тайм-аут. Сравнение моделью и сопоставление в этом проходе не выполнялись.

## Разделение чтения и подготовки фильтра

Полный список кандидатов по-прежнему ограничен 256 строками и не обрезается. Если список превышает предел, драйвер получает отдельный контекст только для подготовки фильтра: полные слова слева, их состояния, исходную позицию, уникальную панель товаров и количество строк в ней. Поля `Products` и списка кандидатов в таком контексте отсутствуют. Он записывается в `filter-context.json`, а не в файл полного наблюдения.

Контекст проверяется дважды с паузой: источник, слова, состояния, панели и счётчик должны совпадать. Проверка всей исходной таблицы и выделения после чтения остаётся обязательной. Отдельный тип исключения отличает превышение числа товаров от ошибки чтения слов, смены документа или неоднозначной панели. Другие ошибки не запускают этот путь.

План включает только добавление звёздочек у уже наблюдавшихся слов. План ограничен, проверяется до первого действия и не строится повторно в цикле. Каждое изменение проходит прежние проверки строки и точного попадания по звёздочке, после него снова читается интерфейс. Уже отправленные выделения и фильтры не повторяются.

Автоматическая подготовка разрешена только явно отмеченным вызовам из чата: первому чтению текущего прайса и проверенному выбору следующей строки. Чтение перед подтверждённой привязкой и после неё не включает фильтры. При возврате к отложенной позиции сначала проверяется документ и целевая строка; если уже исходное чтение слишком широкое, возврат останавливается до выбора и требует ручного сужения.

Внешние операции сравнения, откладывания пустой позиции, перехода к следующей и сопоставления получают только полный ограниченный список. Если допустимых новых фильтров нет или после плана список всё ещё слишком широк, UNIX останавливается на текущей строке с понятной причиной. Это не считается отсутствием кандидатов. Разрешение привязки не выдаётся и не восстанавливается.

## Проверка результата

Локально прошли 135 проверок C# наблюдения и фильтрации, весь GingerChat.Smoke, 164 Python-теста планирования и переходов, три проверки связности агента, 25 искусственных сценариев рабочего PowerShell-фрагмента, проверки filter-only и search-wait, компиляция импорта драйвера. Windows Desktop Release x64 собран; прежнее предупреждение CS0649 в AdaptiveUi осталось. Новые проверки добавлены в Windows CI.

Сценарии охватывают изменение счётчика, панели, источника и слов, переход 278 → 300 → 2 кандидата, исчерпание плана, отмену, отсутствие повторного ввода и запрет передавать неполный список как пустой. Реальное сужение 278 кандидатов новым кодом ещё требуется проверить после установки; успешное сопоставление этим исправлением пока не подтверждено.

## Перечитывание при завершении поиска после переполнения

28 ноября установлен и запущен релиз 79c68d6. Новый проход Ginger после установки
не подтверждён: штатный инструмент управления Windows читает окно UNIX, но ввод
не привёл к запуску задания; `set_value` завершился ошибкой CacheRequest
`0x80070057`, а клик — `coordinate input geometry is unavailable`.

Независимый искусственный прогон обнаружил ещё два преждевременных отказа:
после сообщения о 278 кандидатах список успевает сократиться до 256 или меньше;
либо слова поиска ещё относятся к предыдущей позиции. Контекст только для фильтров
отклонял оба состояния обычной ошибкой, поэтому ожидание результата не продолжалось.

Теперь эти два состояния возвращают отдельный `GingerSearchPendingException`.
Перед сигналом проверяются источник, неизменность счётчика и окно. Контекст
не публикуется и не превращается в пустой список. Рабочий цикл сверяет всю таблицу
и выделение с исходным наблюдением, затем допускает ровно одно новое чтение.
Повторная незавершённость останавливает операцию; неоднозначные панели, смена
товара, состояния слов и остальные ошибки не становятся поводом повторять действия.
Перед принятием окончательного снимка снова выполняется полная сверка таблицы.

Это повтор чтения, а не `Select`, `Filter`, `Prepare` или сопоставления.
Предел списка 256 и отдельное подтверждение привязки сохраняются. В исходных
журналах поиск кандидатов занимал 21–22 секунды, финальная сверка ещё около семи.
Поэтому первый повтор нового типа состояния не зависит от истечения прежнего
десятисекундного таймера за время самого чтения. Общий лимит процесса в 120 секунд
и пользовательский Stop остаются в силе.

Проверки исправления: 20 сценариев рабочего цикла ожидания, 49 сценариев
`Prepare`/`Select`/`Filter`/`Observe`, проверки извлечённых native-методов,
135 C# проверок наблюдения и 117 Python-тестов планирования прошли локально.
Проверены также медленное первое чтение, отдельные пределы для busy и pending,
второе незавершённое наблюдение, смена таблицы/выделения и отсутствие сохранённого
контекста при ошибке. Windows Desktop Release собран без ошибок и предупреждений;
драйвер компилируется из исходников и из папки сборки, упакованные скрипты совпадают.
Эти проверки искусственные и не доказывают успешное сопоставление реального прайса.

## Остановка фильтрации при достижении списка для сравнения

28 ноября в реальном проходе установленной b8b6832 прежняя остановка на 278
кандидатах была пройдена. Для строки `LM White Label ALDHEYX 100мл EDP` после
включения `ALDHEYX` драйвер прочитал полный список из десяти кандидатов. Затем
общий исполнитель продолжил заранее составленный план: включил `White`, получил
ноль и включил `Label`. Пустой список был повторно прочитан и строка сохранена
для разбора. Проблема была в лишних фильтрах: доступный список для сравнения
исчез до обращения к модели. Наличие кандидатов само по себе не подтверждает
правильную пару, а этот ноль не доказывает отсутствия товара в каталоге.

Теперь чат передаёт свой предел десять в сессию фильтрации. После каждого
действия сначала проверяются отмена, исходная строка и изменение только заданной
звёздочки. При полном непустом списке из одного–десяти кандидатов оставшиеся
шаги плана не выполняются: возвращается весь свежий снимок для сравнения.
Это действует при первом чтении с переполнением, переходе к следующей строке
и повторном разборе отложенной позиции. Уже ограниченный список не требует
нового планирования. В журнале появляется сообщение об остановке сужения.

Общий исполнитель по-прежнему проверяет весь план до первого действия. Он не
снимает звёздочки, не возвращается к старому снимку, не повторяет ввод и не
сопоставляет товар. Пустой результат не считается достигнутой целью поиска.
Если список остался слишком широким, действуют прежние ограничения; обрезки
списка нет. Явная подготовка фильтров вне чата, без заданной цели, сохраняет
прежнее поведение. Неверный предел отклоняется до чтения или ввода.

Локально прошли 262 проверки исполнителя фильтров и 420 проверок рабочего пути
чата. Включены искусственные переходы 278 → 10, 11–256 → 1–10, отмена и смена
строки при достижении предела. Windows Desktop Release x64 собран без ошибок
и предупреждений; независимая проверка кода не выявила блокеров. Пользовательский
проход не останавливался и его сохранённые фильтры не исправлялись автоматически.
Исправление требует отдельной проверки установленной новой сборки.
