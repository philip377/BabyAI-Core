# Разные формулировки задания Ginger

27 ноября 2026. Для начала подготовки текущей строки больше не требуется одна
точная фраза. Короткие известные команды сохраняют быстрый путь без модели;
остальные сообщения о прайсе, сопоставлении, кандидатах, товарах или номенклатуре
получают отдельный разбор Qwen.

Проверенные примеры: «Давай дальше по прайсу», «Продолжи сопоставлять товары»,
«Ну что, вернёмся к сопоставлению», «Можешь продолжить сопоставление?»,
«Погнали дальше сопоставлять прайс», «Можно тебя попросить продолжить сопоставлять
товары?». Эти формулировки не являются списком команд в коде: модель отдельно
определяет просьбу действовать сейчас, задачу сопоставления и её объём.

## Путь запроса и границы

`ginger.intent.preview` получает только последнее сообщение пользователя,
до 500 символов. История, уроки, текст Ginger и ответы других моделей не передаются
как команды. Для постороннего чата дополнительного вызова нет. Для неоднозначного
короткого «продолжай» без темы пока сохраняется обычный чат: перенос намерения
из истории ещё не реализован.

Явные отрицания, цитаты, сообщения о чужой просьбе и условные/отложенные команды
не запускают подготовку. Для оставшихся фраз выполняется до трёх коротких
классификаций по 64 токена: просьба → задача → область. Некорректный JSON, лишние
или повторённые поля, неизвестное значение и ошибка модели останавливают разбор.
Задания о ценах/остатках не подменяются сопоставлением номенклатуры. Конкретный
поставщик/название товара, количество строк, весь прайс и составные действия требуют
уточнения. Цепочка начинается с выделенной строки; теперь она умеет пройти
уже сопоставленные и пустые после фильтров строки до следующей проверки пары,
но не принимает произвольный выбор товара, количества или другого поставщика.
Подробнее — [отложенные позиции](ginger-chat-deferred.md).

Результат связан с точным исходным сообщением, текущим чатом и единственной
доступной цепочкой `current_row_preview`. Значение `can_match` всегда false.
До завершения разбора сессия Ginger не создаётся. Видна небольшая анимация
«Понимаю задание»; «Стоп» отбрасывает поздний ответ. Смена чата также отменяет
переход. После успешного разбора существующий драйвер заново читает текущий
экран, готовит фильтры и сравнивает кандидатов. Привязка по-прежнему требует
отдельной карточки подтверждения и свежих проверок строки и результата.

Уточнение, отмена и ошибка не передаются общему агенту как запасная исполняемая
команда. Обычный вопрос продолжает обрабатываться обычным чатом. Модель,
разрешения, уроки, оценки и веса этим разбором не изменяются.

## Проверка

- 126 профильных Python-тестов: намерение, история, транспорт, сравнение, чат,
  навигация, голосовой ввод и STT.
- GingerChat.Smoke: известные команды и модельный маршрут, привязка к запросу,
  фиксированная область, неизвестный/повреждённый ответ, остановка до и после
  ответа; прежние проверки подтверждений, оценок и уроков.
- Локальная Windows Desktop Release x64 собирается. Существующее предупреждение
  CS0649 в AdaptiveUi сохраняется.
- Настоящая Qwen3-8B-Q4_K_M через Vulkan: 51/51 сообщений из
  `tests/fixtures/ginger_chat_intent_cases.json`, включая 16 команд.
  Полный разбор команды занимал около 2–2,5 секунд с загруженной моделью;
  первый запрос с загрузкой — 6,27 секунды на проверенном ПК.

Одношаговая классификация первоначально принимала сообщения о состоянии за
команды. Разделение вопросов и независимые ограничения проверены повторно;
результат на этом наборе не доказывает безошибочность на любых будущих фразах.
Новая Windows CI и установленный UI проверяются отдельно. Реальные действия
в Ginger в этой проверке не выполнялись. Ручная проверка пользователя запланирована
на вечер; прежний сбой Computer Use не обойдён.

Повторить проверку модели без доступа к Ginger можно через
`scripts/evaluate-ginger-intent.py`, указав локальные `--model`, `--runtime`,
`--gpu-layers` и путь отчёта `--output`. Модель открывается один раз и закрывается
по завершении. Это дополнительная проверка с настоящей моделью; обычная CI
использует подставные ответы для проверки маршрута и защитных условий.

## Исправление после ручной проверки

На просьбу «продолжим сопоставление?» пользователь получил «Ответ о намерении
не относится к текущему запросу», хотя движок успешно вернул результат.
Постоянный Python worker добавляет транспортное поле `id`; интерфейс ожидал
ровно шесть полей и отвергал ответ с седьмым полем. Короткая явная команда
обходила модельный маршрут, поэтому работала.

Парсер теперь принимает шесть полей команды и необязательный целочисленный
транспортный `id`, уже связанный мостом с ожидающим запросом. Проверка точного
исходного сообщения, фиксированной области и `can_match=false` сохраняется.
Неизвестные или повторённые поля, отрицательные/нецелые идентификаторы, чужой
текст, изменённые пробелы и Unicode не получают послаблений.

Регрессии проверяют реальную форму ответа worker, исходную фразу с вопросительным
знаком, точное связывание Unicode/пунктуации и отказ при подмене. Это исправление
обмена между интерфейсом и движком, а не новое обучение весов Qwen. Оно само по
себе не доказывает правильную классификацию любой новой фразы моделью.
