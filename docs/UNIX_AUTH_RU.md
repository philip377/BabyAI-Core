# UNIX — централизованная авторизация (этап 1)
Дата: 2026-11-03. Статус: проектирование и SQL-основа; НЕ включено в релиз.

## Решение
- Supabase Auth для логина/пароля, PostgreSQL для ролей и аудита.
- Пользователи работают с разных ПК; локальная модель UNIX и рабочие данные Ginger не отправляются в Supabase.
- Регистрация только по приглашению. В Supabase нужно отключить публичную регистрацию.
- Административные операции выполняет доверенный серверный API/Edge Function, а не клиент WinUI.
- `service_role` и другие серверные секреты **никогда** не включаются в Desktop, установщик, репозиторий или клиентские логи.
- Клиентский public/anon key допустим в Desktop только для Auth API; доступ к таблицам схемы `unix` отозван.
- JWT подтверждает личность, но не заменяет проверку прав. Сервер перепроверяет действующую роль, статус пользователя, нужный scope и возможность отзыва доступа при каждом защищённом действии.
- Локальный AgentExecutor тоже проверяет разрешение и требует отдельное подтверждение опасных действий. Запрет по умолчанию при недоступности сервера или истёкшем разрешении.
- Права на доступ к конкретному ПК, Workspace и Ginger не следуют автоматически из роли. Требуются отдельные ограничения по устройству/рабочему пространству.
- Аудит должен записываться сервером, не самим клиентом. Логи не должны содержать паролей, токенов, содержимого Ginger и секретов.
- Хранение сессий на Windows: OS credential vault/DPAPI; никогда plaintext в SQLite или настройках.
- Предусмотреть смену пароля, MFA для Owner, rate limits, отзыв сессий и восстановление доступа.
- Первая учётная запись Owner создаётся только через отдельную проверенную административную процедуру. Никаких дефолтных паролей, открытого signup или автоматического назначения Owner первому зарегистрировавшемуся.

## Данные
Миграция: `supabase/migrations/20261103_unix_auth_foundation.sql`.
Таблицы `unix.profiles`, `unix.roles`, `unix.permissions`, `unix.user_roles`, `unix.role_permissions`, `unix.audit_events`.
Supabase Auth хранит credentials и refresh sessions. Отдельная таблица с паролями не нужна.

## План внедрения
1. Создать Supabase проект в аккаунте владельца, включить invite-only и MFA.
2. Применить миграцию; проверить RLS и запрет прямого чтения/изменения ролей обычным пользователем.
3. Реализовать серверные endpoints: current-user, effective-permissions, invite, suspend, set-roles, audit. Проверка JWT, RBAC, scope и аудит обязательны.
4. Создать Owner вручную через доверенную административную процедуру; проверить отсутствие пути самоповышения привилегий.
5. Реализовать WinUI login/logout, восстановление сессии и управление пользователями; не ломать существующий интерфейс.
6. Протянуть principal/permissions в Agent Runtime и Ginger driver; проверить deny-by-default, смену ролей во время сессии, потерю сети и отзыв доступа.
7. Windows CI: тесты подмены JWT, изменения ролей, доступа между пользователями/Workspace и отсутствия утечек токенов.
8. После приёмки постепенно переносить Ginger-функции в основной UI.

## Текущее ограничение
Без проекта Supabase, endpoint и секретов, созданных владельцем, настоящие регистрация и вход пока не работают. Эта ветка — безопасная основа, не готовая авторизация.
