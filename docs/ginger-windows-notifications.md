# Уведомления Ginger в Windows

UNIX отправляет локальное уведомление Windows по итогам операции Ginger. Оно попадает в центр уведомлений; показ всплывающего баннера и звук определяет Windows. Уведомления не требуют интернет-сервиса. Результат остаётся в чате или журнале агента.

## Какие результаты сообщаются

- **Пара готова к подтверждению** — в чате действительно создана карточка одной пары. Предложение модели без карточки недостаточно. В окне агента это предложение, которое ещё требует проверки и отдельного подтверждения.
- **Нужна ручная проверка** — нет однозначного кандидата, поиск не дал кандидатов или безопасная привязка заблокирована.
- **Сопоставление проверено** — результат уже перечитан и подтверждён в Ginger.
- **Строка уже сопоставлена** — это прочитанное состояние, новое действие не выполнялось.
- **Чтение завершено / проход завершён** — можно открыть данные или итог прохода. В автоматическом проходе уведомление приходит один раз, а не после каждой строки.
- **Работа остановлена / требуется внимание** — итог отмены или ошибки. Это не обещание отсутствия изменений: предыдущие действия прохода могли завершиться.
- **Объяснение разобрано** — понимание урока готово к проверке, сохранение урока остаётся отдельным действием.

Промежуточные этапы продолжают отображаться в чате. Подготовка фильтров внутри запроса модели не создаёт дополнительного уведомления «готово».

## Нажатие на уведомление

Нажатие только раскрывает UNIX и открывает связанный чат. Оно не запускает новый проход, не подтверждает пару, не сохраняет урок и не меняет разрешения.

Если Ginger ещё выполняет действие, открытие откладывается до окончания работы, чтобы окно UNIX не закрывало проверяемую строку. При открытии уже выбранного чата его карточка подтверждения сохраняется. При перезапуске приложения одноразовое подтверждение не восстанавливается: понадобится новое чтение Ginger. Открытый диалог или ожидающее разрешение не закрываются ради перехода в другой чат.

Уведомления содержат фиксированные тексты без названий поставщиков, товаров, цен или подробностей ошибок. Подробности видны внутри UNIX. Срок хранения уведомления — до семи дней, если пользователь или Windows не удалит его раньше.

## Windows и установка

Используется `Microsoft.Windows.AppNotifications.AppNotificationManager`, уже входящий в Windows App SDK приложения. Обработчик нажатия регистрируется до регистрации уведомлений. Повторный запуск текущей версии перенаправляется в существующий процесс до создания окна и движка.

В Windows App SDK 2.3.1 библиотека `Microsoft.WindowsAppRuntime.Insights.Resource.dll` пропущена в self-contained комплекте. Это мешает регистрации уведомлений с ошибкой `0x8007007E`. Сборка UNIX извлекает только эту библиотеку из официального Runtime NuGet-пакета той же версии и архитектуры и включает её в выходные файлы и установщик. Отдельный системный runtime или MSIX не устанавливается. При отсутствии файла сборка завершается ошибкой. Ошибка SDK: [Microsoft/WindowsAppSDK #6774](https://github.com/microsoft/WindowsAppSDK/issues/6774).

Установленная программа использует постоянный идентификатор отправителя; сборки разработчика изолированы от него. После обновления проверяется выбранный `current.json` и актуализируется только собственная регистрация запуска уведомлений. Старые версии без этой реализации не участвуют в перенаправлении запусков.

Если уведомления отключены в Windows или недоступны, работа Ginger и запись результата продолжаются. Причина отказа записывается в `logs/desktop-startup.log`. UNIX не меняет настройки уведомлений Windows. Отправка в Windows не доказывает, что пользователь увидел баннер: это проверяется отдельно на устройстве.

## Проверка

`tests/GingerChat.Smoke` проверяет различение предложения и подтверждённого результата, отмену/ошибки и решение о навигации без управления реальным Ginger. Сборка Windows проверяет интеграцию SDK.

27 ноября 2026 года на Windows 10 22H2 проверена настоящая доставка через тот же сервис: отдельный диагностический процесс отправил одно тестовое уведомление, а `GetAllAsync` подтвердил его наличие в центре уведомлений (ID 3457). Тестовое уведомление удалено; последующая проверка подтвердила отсутствие и нормальное завершение сервиса. Проверка использовала отдельный идентификатор разработчика, без запуска Ginger или изменения установленного приложения. Нажатие уведомления и переход в настоящий чат через Windows UI в этой проверке не выполнялись.

Регистрация `AppInstance` и его освобождение должны выполняться на одном UI-потоке. Консольная диагностика без `SynchronizationContext` сначала завершалась аварийно при очистке: это [известная особенность SDK #6447](https://github.com/microsoft/WindowsAppSDK/issues/6447). Диагностический процесс исправлен на один поток и завершился успешно; обработчики WinUI приложения сохраняют UI-поток.

Для проверки установленной версии: выполнить подготовку текущей строки через чат, посмотреть итог в центре уведомлений Windows, нажать уведомление и убедиться, что открылся нужный чат с сохранённой карточкой. Затем отдельно подтвердить пару и проверить второе уведомление о результате. Нажатие старого уведомления во время нового прохода не должно вмешиваться в работу драйвера.

Документация Microsoft: [регистрация и активация](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.windows.appnotifications.appnotificationmanager.register), [уведомления в self-contained приложениях](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/self-contained-deploy/deploy-self-contained-apps#dependencies-on-additional-msix-packages).
