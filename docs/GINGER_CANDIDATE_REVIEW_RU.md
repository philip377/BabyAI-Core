# Объяснение кандидатов — 02.11.2026

Добавлен локальный отчёт по наблюдаемым строкам Ginger. Он использует существующий разбор названий, разделяет различия и недостающие данные по названию, бренду, объёму, концентрации, тестеру и штрихкоду. Отсутствие слова «тестер» не считается доказательством обычного товара. Обозначение ash/l отмечается как неподтверждённое; словарное правило для него не создаётся.

Запуск из исходников: `python scripts/windows/ginger-candidate-review.py snapshot.json --output review.json`. Принимается снимок кандидатов или поле candidate_snapshot диагностического отчёта. Выходной файл создаётся исключительно как новый: существующий отчёт не перезаписывается. Вход ограничен размером и числом строк, противоречащие режиму чтения разрешения отклоняются. Номера наблюдаемых строк не превращаются в SKU.

Проверено на свежем чтении третьей строки прайса: обе найденные карточки HOMME отличаются названием от MAN TOO; для тестера явно показывается известный признак кандидата и неизвестный признак исходной позиции. Исходные данные и полученный отчёт остаются локально. Даже одинаковые названия не подтверждают идентичность карточки или завершение поиска. Пустой список не доказывает отсутствие товара.

Проверки: полный Python-набор перед последним добавлением теста запуска — 661 passed, 1 skipped. После добавления проверки запуска из другого каталога и защиты от перезаписи целевые тесты — 32 passed. Изменения не затрагивают ввод в Ginger, UI, STT/VAD, разрешения или алгоритм существующих рекомендаций. Это отдельный диагностический отчёт; интеграция в Agent Runtime и единая последовательность управления фильтрами ещё не завершены.
