# Локальная очередь навигации Ginger

Добавлен `babyai.ginger_price_queue.PriceVisitQueue`. Он сохраняет порядок отмеченных документов и результаты наблюдения их открытия. Модуль не обращается к Ginger, не нажимает кнопки, не меняет товары и не заменяет разрешения Agent Runtime.

## Контракт

1. `create(report)` создаёт новый план в отдельном пустом каталоге по полному отчёту `ReadPrices`: номер, поставщик, дата и галочка каждой строки. Неотмеченные строки также сохраняются, чтобы замечать изменение исходного списка. Порядок остаётся таким, каким его вернул интерфейс. Документы одного поставщика не объединяются.
2. `next(fresh_report)` сравнивает свежий список с планом и возвращает следующий отмеченный документ. Любое изменение порядка, номера, поставщика, даты или галочки останавливает продолжение. Новая сессия Ginger допустима только после свежего чтения и совпадения этих наблюдаемых полей; это не доказательство идентичности базы или сервера.
3. `begin(fresh_report)` создаёт исключительную запись намерения и возвращает номер попытки и документ. Контроллер должен выполнить это **до** навигации. Пока исход не подтверждён, следующий `begin` и `next` запрещены, в том числе после перезапуска Python.
4. `observe(attempt, document)` принимает номер попытки и результат доверенного чтения документа из UI: `Number`, `Supplier`, `CanWrite=false`. Несовпадение оставляет попытку незавершённой. После успешной записи следующий документ становится доступен.

`observed_documents` — число документов, открытие которых подтвердил вызывающий контроллер. Это не число обработанных прайсов: все товары документа могут оставаться непроверенными. Даже конец очереди возвращает `products_processed=false` и `can_write=false`. Идентификаторы товаров здесь не создаются.

## Хранение и сбои

В отдельном каталоге плана лежат `plan.json` и последовательные файлы событий `000001.json`, `000002.json` и далее. Файлы создаются исключительно (`x`), сбрасываются через flush/fsync и не перезаписываются. Соперничающий процесс не может записать то же событие; проигравшая попытка завершается ошибкой. Частичная запись, пропуск номера, неизвестный файл, неверный переход или повреждённый JSON блокируют воспроизведение.

Гарантия не включает абсолютную сохранность файловой системы при отказе оборудования. Не добавлены автоматическое удаление незавершённой попытки, пересоздание плана, пропуск документа или восстановление после повреждения. Прямое редактирование файлов не является разрешённым механизмом продолжения. Файлы содержат данные поставщиков и должны оставаться в локальном профиле пользователя.

## Диагностический интерфейс

`python -m babyai.ginger_price_queue` предоставляет операции `create`, `status`, `next`, `begin`, `observe` с явным `--directory`, а для чтения отчёта — `--report`; для `observe` обязателен `--attempt`. Этот CLI читает локальные JSON и ведёт журнал. Он не проверяет достоверность произвольного файла как результата живого UI и не является инструментом для модели: его вызывает только доверенный контроллер после собственного чтения интерфейса. Навигационные разрешения, подтверждение пользователя, проверка выделения и окон остаются обязанностью драйвера.

## Проверено и что осталось

21 новых тестов: порядок при одинаковых поставщиках; сохранение незавершённой попытки после перезапуска; отклонение изменённого списка; неправильного документа; повторного результата; повреждённых и пропущенных событий; конкуренция двух контроллеров; строгие галочки; отсутствие сброса существующего плана; конец очереди без утверждения об обработке товаров. Полный Python-набор: 571 passed, 1 skipped.

Журнал подключён к экспериментальному `scripts/windows/ginger-queue-step.ps1`. Операции: `Initialize` читает уже видимый список и создаёт новый план; `Status` читает только журнал; `Step -ConfirmNavigation` проверяет отсутствие незавершённой попытки, перечитывает список, записывает намерение, выделяет документ и открывает его существующим guarded driver, затем подтверждает номер и поставщика через UI. Несовпадение или ошибка оставляет попытку незавершённой. Не запускайте несколько разных планов против одной сессии Ginger: глобальная блокировка между каталогами ещё не реализована.

Для вызова Python используется фиксированный `ginger-queue-cli.py`, который загружает ядро из того же checkout. Это исключает случайный вызов устаревшего установленного пакета и проблемы кавычек Windows PowerShell. Источник и пути команд не принимаются от модели. Скрипт требует полный checkout, а не только установленный Desktop.

Ручной диагностический harness `GingerDiagnostics.Smoke --queue-controller` ограничивает весь процесс 60 секундами и объём вывода, завершает дочерние процессы при тайм-ауте; для `Step` обязателен `--confirm-navigation`. Прямой запуск PowerShell без harness не даёт внешнего тайм-аута для зависшего COM. Эти режимы не запускаются в обычном CI. `ConfirmNavigation` — подтверждение экспериментального запуска, не замена разрешений Agent Runtime.

На реальном Ginger создан локальный план из 48 прайсов и выполнены два шага в разных процессах. После каждого открытия сверены номер и поставщик; журнал показал `observed_documents=2`, `pending_attempt=null`, `products_processed=false`. Счётчик означает только открытие, не обработку товаров. Возврат к списку пока выполняется отдельным вызовом проверенной навигации; автоматического цикла через все документы нет.

Дополнительно проверены фиксированный Python entrypoint из другого рабочего каталога и отказы Windows-контроллера без подтверждения / с незавершённой попыткой до доступа к UI. Эти проверки добавлены в Windows Desktop CI. Всего локально: 23 теста очереди; полный Python-набор — 573 passed, 1 skipped. Следующий этап — согласовать переходы очереди с чтением товаров, возвратом к списку и разрешениями штатного Runtime. Никакие данные Ginger не изменялись.
