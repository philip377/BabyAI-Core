# Подключение контроллера — 02.11.2026

Добавлен scripts/windows/ginger-filter-step.ps1: Initialize создаёт план из StepsFile, Step выполняет ровно один подтверждённый шаг, Observe только сверяет незавершённый шаг, Status читает журнал. Операция Step требует ConfirmNavigation. Эксклюзивная файловая блокировка действует на весь запуск контроллера одного плана. Остальные отдельные инструменты не объединены этим замком; параллельные испытания ими не поддерживаются.

Перед вводом контроллер читает контекст, журнал проверяет его по плану и сохраняет begin на диск. Только затем драйвер получает точное ожидаемое состояние слов; драйвер вновь проверяет его перед нажатием. Действие берётся из сохранённого pending_action, а не из устаревшего статуса next_step. После двух чтений журнал принимает observe и отдельно сохраняется отчёт по кандидатам. Если отчёт не удастся сохранить после успешного observe, шаг останется наблюдённым — повторное нажатие для исправления отчёта недопустимо.

В диагностический запуск добавлен --filter-controller Step|Observe|Status с пределом 120 секунд, скрытым процессом и остановкой дочерних процессов при таймауте. Для Step требуется --confirm-navigation. После неопределённого исхода доступно только Observe. Initialize пока вызывается отдельным PowerShell-скриптом.

Реальная проверка: создан план MAN=true, TOO=true для прежней третьей строки. Первый запуск подтвердил уже включённый MAN; второй включил TOO. Между запусками состояние восстановлено из журнала. Оба шага завершены, кандидатов стало 0. Пустой результат не доказывает отсутствие товара или завершение поиска. Связывания карточек не выполнялись. На время активного шага попытка открыть блокировку вторым владельцем была отклонена.

Первое создание плана остановилось до ввода из-за формы массива ConvertFrom-Json в Windows PowerShell. Исправлено явным построением списка объектов. Проверки: полный набор до последних двух регрессионных тестов — 697 passed, 1 skipped; после исправления целевые тесты — 24 passed. Диагностическая сборка и её проверки завершились успешно. Тесты контроллера добавлены в Windows Desktop CI.

Следующий этап — выбор безопасного плана уточнения поиска и подключение к проходу строк прайса. Контроллер пока выполняет только явно заданные шаги; самостоятельный выбор фильтров, доказательство завершения поиска и интеграция Agent Runtime не завершены.

# Журнал последовательности фильтров — 02.11.2026

Добавлен FilterPlan и локальная команда scripts/windows/ginger-filter-plan.py. План фиксирует процесс, документ, выбранную строку, цену, текущую связь, обе панели и исходное состояние слов. От 1 до 32 шагов задают уникальное наблюдаемое слово и желаемое состояние звёздочки. Журнал не отправляет ввод и не предоставляет права на сопоставление.

Операции: create создаёт новый каталог плана; begin с --confirmed сохраняет намерение для очередного шага; observe сверяет два наблюдения; status показывает прогресс. JSON для create содержит context, process_id, steps; для begin — context и process_id; для observe — first, second и process_id. Общие параметры: --directory и --report (кроме status). Существующий план не перезаписывается.

Каждое событие создаётся исключительно как новый файл и сбрасывается на диск. При перезапуске вся последовательность проверяется заново. Незавершённый begin блокирует следующие шаги: доступно только наблюдение, автоматический повтор ввода запрещён. Повреждённое или пропущенное событие, изменение процесса, исходного товара, цены, другого фильтра или панели блокируют продолжение. Статус steps_observed означает проверенные наблюдения шагов, а не завершение поиска или обработки товара.

Проверки: 18 новых тестов, полный Python-набор 693 passed, 1 skipped. На сохранённых данных настоящего Ginger проверен план из двух уже включённых фильтров MARBERT и MAN с восстановлением объекта журнала между шагами. Это воспроизведение сохранённых наблюдений: новых нажатий и живой проверки свежести в этом испытании не было. Данные остаются локально. Новые тесты включены в Windows Desktop CI.

Ограничение: журнал пока не подключён к контроллеру последовательных нажатий. Следующий этап — перед каждым действием передавать контроллеру точное ожидаемое состояние плана, а после него сохранять наблюдение. Нельзя просто вызвать старый одиночный запуск без такой привязки: он может увидеть уже другую строку. Сопоставление, создание карточек и Agent Runtime этим этапом не изменены.
